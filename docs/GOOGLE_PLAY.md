# ขึ้น Google Play — คู่มือทำตามทีละขั้น

แอพ **จันทราพยากรณ์** (package `com.xjanova.juntra`) build ได้ 2 ช่องทางจากโค้ดชุดเดียวกัน

| | ช่อง **play** (Google Play) | ช่อง **direct** (APK บน GitHub) |
|---|---|---|
| ไฟล์ | App Bundle `.aab` | `juntra-X.Y.Z-universal.apk` |
| อัปเดต | Google Play (มีหน้าต่างแจ้งในแอพผ่าน In-App Updates) | ตัวอัปเดตในแอพ (ดาวน์โหลด APK) |
| เติมเครดิต | **Google Play Billing** (แพ็กเครดิต) | พร้อมเพย์ + สลิป |
| สิทธิ์ที่ขอ | INTERNET อย่างเดียว | INTERNET + ติดตั้งแพ็กเกจ (เพื่ออัปเดตตัวเอง) |
| build | `flutter build appbundle --release --flavor play` | `flutter build apk --release --flavor direct` |

ทำไมต้องแยก — นโยบาย Google Play:
- แอพบน Play **ห้ามอัปเดตตัวเอง** และห้ามขอ `REQUEST_INSTALL_PACKAGES` เพื่อการนี้
- **เครดิตที่ใช้ในแอพต้องขายผ่าน Google Play Billing** และห้ามมีปุ่ม/ลิงก์/ข้อความ/QR พาไปจ่ายช่องทางอื่น
  (ประเทศไทยยังไม่อยู่ในโปรแกรม billing ทางเลือกใด ๆ ณ ก.ย. 2569)
- ห้ามขอสิทธิ์เข้าถึงรูปทั้งเครื่อง (`READ_MEDIA_IMAGES`) ถ้าไม่ใช่ฟีเจอร์หลัก
- ต้องลบบัญชีได้ในแอพ + มีหน้าเว็บสำหรับขอลบ, มีลิงก์นโยบายความเป็นส่วนตัวในแอพ, มีปุ่มรายงานเนื้อหาที่ AI สร้าง

ทั้งหมดนี้ทำไว้ในโค้ดแล้ว เหลือขั้นตอนใน Play Console / เซิร์ฟเวอร์ที่เจ้าของต้องทำเอง (ข้างล่าง)

## 0. ก่อนเริ่ม — เช็คบัญชีนักพัฒนา

- **บัญชีแบบบุคคล (personal) ที่สร้างหลัง 13 พ.ย. 2566** ต้องทำ **Closed testing ที่มีผู้ทดสอบ ≥ 12 คน ติดต่อกัน ≥ 14 วัน**
  ก่อนจะขอเปิด Production ได้ — วางแผนเวลาไว้ด้วย (บัญชีองค์กรไม่ติดเงื่อนไขนี้)
- ยืนยันตัวตนนักพัฒนา (Developer verification) ให้เรียบร้อย — ไทยเริ่มบังคับ 30 ก.ย. 2569
  สำหรับแอพที่ติดตั้งจากสโตร์ (Play ลงทะเบียนให้อัตโนมัติเมื่อใช้ Play App Signing)

## 1. สร้างแอพใน Play Console

1. **Create app** → ชื่อ `จันทราพยากรณ์ - แม่หมอจันทรา` (ไม่เกิน 30 ตัวอักษร) · ภาษาเริ่มต้น **ไทย** · App · **Free**
2. **App signing — เลือก "ใช้คีย์ของตัวเอง" (Use existing app signing key)** ⚠️ สำคัญ
   - คีย์ที่ใช้เซ็น APK ตัวเดิมคือ `android/upload-keystore.jks` alias `juntra-upload`
     (cert SHA-256 `C7:1B:0C:9B:32:8D:8F:E6:7A:5F:16:16:3F:C7:10:10:84:14:56:0A:28:23:FA:F3:46:08:77:CC:CB:05:9E:DB`)
   - Play Console จะให้ดาวน์โหลดเครื่องมือ **PEPK** แล้วรันคำสั่งที่มันแสดง (ใส่ keystore + alias เดิม) → อัปโหลดไฟล์ที่ได้
   - ทำแบบนี้ = เครื่องที่ติดตั้ง APK จาก GitHub อยู่แล้ว **อัปเดตผ่าน Play ได้ต่อเลย** ไม่ต้องถอนแอพ/ข้อมูลไม่หาย
   - ถ้าให้ Google สร้างคีย์ใหม่ → เครื่องเดิมต้องถอนแอพก่อนลงจาก Play (ลายเซ็นไม่ตรง)
   - แนะนำเพิ่ม: สร้าง **upload key ใหม่** แยกจาก app signing key (Play Console → App integrity → Upload key)
     แล้วเปลี่ยน secret ใน GitHub เป็น upload key ตัวใหม่ — ถ้า upload key หลุด ขอรีเซ็ตกับ Google ได้
     *(ถ้าทำข้อนี้ APK ช่อง direct ต้องยังเซ็นด้วยคีย์เดิม — ต้องแยก secret สองชุด; ถ้ายังไม่พร้อม ใช้คีย์เดิมอัปโหลดไปก่อนได้)*
3. อัปโหลด AAB แรก **ด้วยมือ** ที่ Testing → **Internal testing** → Create release
   - ไฟล์ AAB มาจาก GitHub Actions: หน้า run ของ workflow **Release** → Artifacts → `play-bundle-<version>`
   - หรือ build เองในเครื่อง: `flutter build appbundle --release --flavor play`
     → `build/app/outputs/bundle/playRelease/app-play-release.aab`

## 2. แพ็กเครดิต (Google Play Billing)

1. **ตั้ง Payments profile** (Monetize → Payments profile / merchant account) + บัญชีธนาคารรับเงิน — ต้องมีก่อนสร้างสินค้า
2. Monetize → Products → **One-time products** → สร้างทีละตัว (ชนิดสินค้าใช้แล้วหมด — consumable เป็นเรื่องของโค้ด ไม่ต้องตั้ง)

   | Product ID (ต้องตรงทุกตัวอักษร) | เครดิตที่ได้ (ตั้งในหลังบ้านเว็บ) | ราคาแนะนำ* |
   |---|---|---|
   | `juntra_credits_50` | 50 | ฿59 |
   | `juntra_credits_100` | 100 | ฿119 |
   | `juntra_credits_200` | 200 | ฿229 |
   | `juntra_credits_500` | 500 | ฿559 |
   | `juntra_credits_1000` | 1000 | ฿1,090 |

   \* Google หักค่าธรรมเนียม **15%** ของรายได้ปีละ $1M แรก (ต้องสมัครโปรแกรม 15% ใน Play Console ไม่งั้นโดน 30%)
   ราคาเป็นการตัดสินใจทางธุรกิจของเจ้าของ — ตั้งให้ครอบค่าธรรมเนียม หรือจะให้เท่าเว็บก็ได้
   (Google ไม่บังคับให้ราคาเท่ากันทุกช่องทาง แต่ **ห้ามบอกในแอพ** ว่าซื้อบนเว็บถูกกว่า)
3. กด **Activate** ทุกตัว
4. จำนวนเครดิตต่อแพ็กแก้ได้ที่เว็บ: **/admin → การเงิน → ตั้งค่าวอลเลต/ราคา → ส่วน "เติมเครดิตผ่าน Google Play"**
   (เพิ่ม/ลบแพ็กได้ Product ID ต้องมีอยู่ใน Play Console และ Activate แล้ว)
5. **License testers** (Setup → License testing) → ใส่ Gmail ของทีม — ซื้อทดสอบได้โดยไม่ถูกเก็บเงินจริง
   *(การซื้อแบบทดสอบถูกเติมเครดิตจริงในระบบ และมีป้าย `test` ใน meta ของรายการ — ใช้กับบัญชีทีมเท่านั้น)*

## 3. ให้เซิร์ฟเวอร์ตรวจการซื้อได้ (service account)

เซิร์ฟเวอร์ `จันทรา.online` ถาม Google ทุกครั้งก่อนเติมเครดิต (ไม่เชื่อแอพ) — ต้องมีกุญแจ service account

1. Google Cloud Console → โปรเจกต์ที่ผูกกับ Play Console → **Enable "Google Play Android Developer API"**
2. IAM → Service accounts → **Create** (เช่น `juntra-billing`) → Keys → Add key → **JSON** → ดาวน์โหลด
3. Play Console → **Users and permissions** → Invite new users → อีเมลของ service account
   → App permissions: เลือกแอพนี้ → ติ๊ก **View financial data** และ **Manage orders and subscriptions**
4. อัปโหลดไฟล์ JSON ขึ้นเซิร์ฟเวอร์ **นอก public_html** เช่น `/home/<user>/secure/google-play.json` (chmod 600)
5. ใส่ใน `.env` ของเว็บ แล้วล้าง cache:
   ```
   GOOGLE_PLAY_SERVICE_ACCOUNT_PATH=/home/<user>/secure/google-play.json
   GOOGLE_PLAY_PACKAGE_NAME=com.xjanova.juntra
   ```
   ```bash
   php artisan config:clear && php artisan config:cache
   ```
6. เช็คที่ /admin → ตั้งค่าวอลเลต/ราคา → ส่วน Google Play ต้องขึ้น **✅ ตั้งค่า service account แล้ว**
7. ต้องมี cron ของ Laravel ทำงาน (`schedule:run` ทุกนาที) — งานที่เพิ่มมา:
   - `googleplay:consume-pending` ทุก 10 นาที (ยืนยันการส่งมอบกับ Google — ต้องทันภายใน 3 วัน ไม่งั้น Google คืนเงินลูกค้าอัตโนมัติ)
   - `googleplay:sync-voided` ทุกชั่วโมง (ลูกค้าขอคืนเงิน/chargeback กับ Google → ดึงเครดิตคืน ไม่ติดลบ)

ยังไม่ตั้ง = แอพช่อง Play **ไม่มีหน้าซื้อเครดิต** (ใช้เครดิตที่มีได้อย่างเดียว) — ไม่ผิดนโยบาย แต่ขายไม่ได้

## 4. อัปโหลดอัตโนมัติจาก GitHub (ไม่บังคับ)

- สร้าง service account อีกตัว (หรือใช้ตัวเดิม) ให้สิทธิ์ **Release apps to testing tracks**
- GitHub → repo `xjanova/juntra` → Settings → Secrets → **`PLAY_SERVICE_ACCOUNT_JSON`** = เนื้อหาไฟล์ JSON ทั้งไฟล์
- จากนั้นทุก release (merge PR ที่ติด label `release:*`) จะอัปโหลด AAB ขึ้น **Internal testing แบบ Draft**
  ให้เข้าไปกด Roll out เอง — ไม่มีอะไรถึงมือผู้ใช้จนกว่าจะกด
- ⚠️ รุ่นแรกต้องอัปโหลดด้วยมือก่อน (ข้อ 1.3) API ถึงจะใช้ได้

## 8. ออกรุ่น

1. merge PR เข้า `main` พร้อม label (`release:minor` ฯลฯ) → auto-bump → tag → workflow **Release**
2. ได้ `juntra-X.Y.Z-universal.apk` บน GitHub Releases (ช่อง direct — ตัวอัปเดตในแอพ APK เห็นเอง)
   และ AAB ช่อง play เป็น artifact ของ run (+ อัปขึ้น Internal testing แบบ draft ถ้าตั้ง secret ไว้)
3. Play Console → Internal testing → ตรวจ → Roll out → ทดสอบบนเครื่องจริง (ข้อ 9)
4. Promote → Closed testing (ครบ 12 คน 14 วันถ้าเป็นบัญชีบุคคลใหม่) → Production

> build number ต้องเพิ่มขึ้นเสมอ (Play ปฏิเสธเลขซ้ำ/ต่ำกว่า) — ตั้งแต่ 5000 ขึ้นไป
> เพราะ APK แบบแยก ABI ที่เคยปล่อยมีเลข 1000×abi+build (arm64 = 2017) เลขต่ำกว่านั้นติดตั้งทับเครื่องพวกนั้นไม่ได้

- [ ] สมัคร/ล็อกอิน (อีเมลหรือเบอร์) — มีลิงก์ข้อตกลง/นโยบายความเป็นส่วนตัวตอนสมัคร
- [ ] วอลเลต → เติมเครดิต: เห็นราคาจาก Google Play → ซื้อด้วยบัญชี license tester → เครดิตเข้าทันที
- [ ] ซื้อแพ็กเดิมซ้ำได้ (consume ถูกต้อง) · ยกเลิกหน้าจ่าย = ไม่มีอะไรเกิด
- [ ] เลือกแพ็กเกจ (มีภาพประกอบ ราคา) → สับไพ่ → เปิดไพ่ → หน้า "แม่หมอกำลังอ่าน" → คำทำนายขึ้นเป็นการ์ด
- [ ] แพ็กเกจที่ใส่วันเกิดได้ (Celtic / 12 เดือน) · 12 เดือนเปิดซ้ำใน 30 วันไม่ได้ (บอกวันที่เปิดได้)
- [ ] คุยต่อกับแม่หมอจากหน้าผล → แม่หมอรู้ว่าเปิดไพ่อะไร
- [ ] ปุ่มรายงานคำทำนาย/ข้อความแชท → แอดมินได้แจ้งเตือน + คิวใน /admin/content-reports
- [ ] ตั้งค่า → เปลี่ยนรหัสผ่าน · ลบบัญชี (ใช้บัญชีทดสอบทิ้ง) → ออกจากระบบ ข้อมูลหาย
- [ ] ตั้งค่า → ตรวจสอบอัปเดต → พาไป Play (ไม่มีการดาวน์โหลด APK ในแอพ Play)
